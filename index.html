SHAP Explanations

Understand why each prediction was made. Build trust. Enable debugging.

What is SHAP?

SHAP stands for SHapley Additive exPlanations. It's a game-theoretic approach to explain the output of machine learning models.

In plain English: SHAP shows you exactly which features (data columns) influenced each prediction and by how much.

Why It Matters

  • Builds trust — You can see exactly why the model made a prediction
  • Enables debugging — If a prediction seems wrong, SHAP helps you understand why
  • Satisfies compliance — Regulators require explainability for AI decisions
  • Improves data quality — SHAP reveals which features are most important

How to Read SHAP

Every KINLU prediction includes SHAP explanations showing:

  • Top features — Which data columns most influenced the prediction
  • Direction of impact — Did this feature increase or decrease the prediction?
  • Magnitude — How much did this feature influence the prediction?
SHAP Example
Churn Prediction for Customer #1234:

Predicted churn probability: 78%

Top factors increasing churn risk:
  • No purchases in 60 days: -45 points
  • Engagement dropped 70%: -30 points
  • Customer age 2 years: +15 points

When to Use SHAP

Always use SHAP for every prediction. It's non-negotiable for:

  • Regulatory compliance (GDPR, CCPA)
  • Building customer trust
  • Debugging model predictions
  • Improving data quality

Data Preparation

Prepare your data for KINLU in 5 steps.

Supported Data Sources

  • CSV upload — Local file upload, drag-and-drop interface
  • Shopify — Automatic sync of orders, customers, products
  • Coming soon: Google Analytics 4, Meta Ads, Klaviyo, Stripe

5-Step Data Preparation Process

  1. Gather Your Data
    Export customer data from your database or CRM. Include all relevant columns (purchase history, engagement, demographics). Go back 12-24 months for best results.
  2. Clean Your Data
    Remove duplicate rows. Remove rows with missing target variable. Standardize date formats (YYYY-MM-DD). Standardize categorical values (lowercase, no extra spaces).
  3. Create Target Variable
    Create the column you want to predict. For churn: "churned" (1 = churned, 0 = active). For revenue: "revenue" (total amount). For segmentation: no target needed.
  4. Format Your CSV
    First row = column headers. One row per customer/order. Save as .csv file (not .xlsx). Use underscores for spaces in column names.
  5. Upload to KINLU
    Click "New Model" → "Upload CSV". Select your file. Map columns to KINLU fields. Review data preview. Click "Create Model".

Column Requirements

  • Unique identifier: Customer ID, order ID, or transaction ID (required, no duplicates)
  • Target variable: The column you want to predict (e.g., "churned", "revenue")
  • Features: Supporting data (purchase history, engagement, demographics)
  • Date columns: Timestamps for time-series models (format: YYYY-MM-DD)

Data Quality Requirements

  • Missing values: Up to 30% missing data is OK; KINLU handles it
  • Duplicates: Remove exact duplicates before upload
  • Outliers: Extreme values are OK; KINLU is robust
  • Imbalanced classes: OK for classification (e.g., 95% non-churned, 5% churned)

Common Data Preparation Mistakes

❌ Mistake 1: Including Future Data
Don't include data from after your target date. This causes "data leakage" and inflates accuracy.
❌ Mistake 2: Missing Target Variable
Every row must have a value for what you're predicting. Remove rows with null values in target column.
❌ Mistake 3: Wrong Date Format
Use YYYY-MM-DD format. Don't use "Jan 1, 2024" or "01/01/2024".
❌ Mistake 4: Too Many Categories
Categorical columns with 1000+ unique values reduce model quality. Limit to top 50 categories.
❌ Mistake 5: Mixing Units
If revenue column has both USD and EUR, convert to one currency first.

Understanding Performance Metrics

How to evaluate if your model is good.

Classification Models (Churn, Segmentation, Product Recommendation)

Metric What It Means Good Score
Accuracy % of correct predictions > 80%
Precision % of positive predictions that were correct > 75%
Recall % of actual positives that were found > 70%
AUC-ROC Overall model quality (0.5 = random, 1.0 = perfect) > 0.75

Regression Models (Revenue Forecast, LTV, Next Purchase)

Metric What It Means Good Score
RMSE Average prediction error (lower is better) < 10% of average
MAE Mean absolute error < 15% of average
R² % of variance explained (0 = bad, 1 = perfect) > 0.6

Why Might Performance Be Low?

🔍 Debugging Low Accuracy
Possible causes:
  • Insufficient data (need at least 500 rows; 5,000+ is better)
  • Poor data quality (missing values, outliers, inconsistent formatting)
  • Weak features (columns don't predict target well)
  • Imbalanced target (99% of one class, 1% of another)
  • Target leakage (features include info from after target date)

Improving Model Accuracy

  1. Add more data (if possible)
  2. Improve data quality (fix missing values, remove outliers)
  3. Add better features (columns that actually predict target)
  4. Remove noisy columns (features with no correlation to target)
  5. Retrain monthly (keeps model fresh)

Troubleshooting

Solutions to common issues.

Data Quality Issues

Problem: Too many missing values
KINLU handles up to 30% missing data automatically. For more, either fill with mean/median or remove rows with missing target variable.
Problem: Categorical columns with too many unique values
Limit to 50 unique values per column. Group rare categories into "Other".
Problem: Imbalanced target (95% vs 5%)
This is OK. Use AUC-ROC instead of accuracy to evaluate model quality.

Model Performance Issues

Problem: Low accuracy
Try: (1) Add more data, (2) Add better features, (3) Remove noisy columns, (4) Check for data leakage, (5) Retrain with updated data.
Problem: Model training failed
Check: (1) Missing target variable, (2) All rows identical, (3) Extreme outliers. Contact support if unsure.
Problem: Model stuck in training
